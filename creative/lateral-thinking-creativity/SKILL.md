## When to Use
Solve problems that don't have obvious solutions. Use when stuck on a creative block, need unconventional approaches, are redesigning something from scratch, or facing a problem that resists linear thinking.

## Core Concepts
- **Lateral thinking** (Edward de Bono): Approach problems sideways rather than head-on. Challenge assumptions, reframe the problem, look for provocative moves.
- **SCAMPER**: Substitute, Combine, Adapt, Modify, Put to another use, Eliminate, Reverse. A systematic creativity checklist.
- **First principles thinking**: Break a problem down to its fundamental truths, then rebuild from scratch. Don't reason by analogy.
- **Reverse brainstorming**: Instead of "how do we solve X?", ask "how could we make X worse?" Then invert the answers.
- **Random input**: Introduce an unrelated concept and force connections. "How is our product like a garden?"
- **Constraint as catalyst**: Adding constraints often increases creativity. "Design a solution in 3 hours with $0 budget."

## Workflow
1. **Frame the problem**: Write the problem as a question. "How might we..." is the gold standard.
2. **Challenge assumptions**: List every assumption about the problem. Question each one. "What if this wasn't true?"
3. **Divergent brainstorm**: Generate 50+ ideas without judgment. Quantity before quality.
4. **Apply SCAMPER**: Run each SCAMPER prompt against the top ideas. What happens if you combine them? Reverse them? Eliminate a core feature?
5. **Convergent selection**: Group ideas, find patterns, identify the 3-5 most promising directions.
6. **Prototype rapidly**: Build the simplest version of each promising idea. Test before committing.
7. **Cross-pollinate**: Look at how other industries solve similar problems. Apply their solutions to yours.

## Key Patterns
```markdown
# SCAMPER Applied to Any Problem
For each letter, force an answer:

S - Substitute: What component could we replace?
  "What if instead of a subscription, we used a pay-per-use model?"
  
C - Combine: What two things could become one?
  "What if the onboarding tutorial was also the first real task?"
  
A - Adapt: What else is this like?
  "How does a restaurant handle reservations? Can we adapt that?"
  
M - Modify/Magnify: What if we 10x this feature?
  "What if the free tier was so good nobody needed to upgrade?"
  
P - Put to another use: What else could this be used for?
  "Could our error logs become a user analytics feature?"
  
E - Eliminate: What can we remove entirely?
  "What if we removed the sign-up process entirely?"
  
R - Reverse: What if we did the opposite?
  "What if users set the price instead of us?"

# "How Might We" Reframing
Original: "Our retention rate is too low"
HMW 1: "How might we make users feel successful in the first 5 minutes?"
HMW 2: "How might we make the product harder to leave?"
HMW 3: "How might we turn our most active users into teachers?"

# Random Input Exercise
1. Pick a random word (open a dictionary to any page)
2. List 5 properties of that word
3. Force a connection between each property and your problem
4. Generate 3 ideas from each connection
5. Example: Random word = "bridge"
   - Connects two things → What two things in our product should be connected?
   - Carries weight → What heavy lifting does the user do that we could carry?
   - Built over obstacles → What obstacles prevent user success?
```

## Pitfalls
- **Judging ideas too early**: Premature evaluation kills creativity. Generate first, judge later.
- **Staying in your domain**: The best lateral solutions often come from outside your industry
- **Linear thinking about creative problems**: If the obvious solution worked, you wouldn't be stuck
- **Brainstorming alone**: Group creativity generates more diverse ideas. Solo brainstorming tends to repeat patterns.
- **Not prototyping**: Ideas are worthless without validation. Build to think.

## Verification
- Generated 50+ ideas before evaluating any
- Applied at least 3 SCAMPER prompts to the problem
- Reframed the problem at least 3 different ways
- Looked at solutions from at least 2 other industries
- Prototyped at least 2 ideas before committing to one
- Asked "what assumptions am I making?" and challenged each one
